**Feature level ZF-4f1745**

* [`POST /agent/profiles`](/api/create-agent-profile),
  [`PATCH /agent/profiles/{profile_id}`](/api/update-agent-profile): Added
  the `agent_role`, `avatar_shape`, `avatar_color`, `model_preset`,
  `monthly_budget_microunits`, `work_skills`, and `work_tools` fields. An
  update that omits one of these fields keeps its current value.
* [`POST /agent/profiles`](/api/create-agent-profile),
  [`PATCH /agent/profiles/{profile_id}`](/api/update-agent-profile): A name
  that an active user or bot in the organization has, or a reserved name,
  now fails with the `agent_name_unavailable` error code.
* [`POST /agent/profiles`](/api/create-agent-profile): A user who can create
  agents can now create an `answer` agent on the organization's work runner
  without access to that runner. The server then picks the model provider
  and the harness.
* [`GET /agent/profiles`](/api/list-agent-profiles),
  [`GET /agent/profiles/{profile_id}`](/api/get-agent-profile): Profiles
  also report the fields above, a `kind` (`work` or `coding`), a
  `model_label`, and `is_builtin`.
* [`GET /agent/profiles`](/api/list-agent-profiles),
  [`GET /agent/profiles/{profile_id}`](/api/get-agent-profile): Profiles
  also report `access_grants`: the channels, Drive folders, and MCP
  connections that the agent can reach.
* [`POST /agent/grants`](/api/create-agent-grant): A guest can no longer
  receive an agent grant, and no grant applies to a guest.
* Added [`GET /agent/profiles/stats`](/api/get-agent-profile-stats). It
  reports `tasks_per_week` and `approve_rate` for every profile that you can
  see.
* Added [`GET /agent/audit`](/api/get-agent-audit), a feed of the recent
  activity of the agents that you can see.
* [`POST /agent/profiles/{profile_id}/pause`](/api/pause-agent-profile): An
  organization administrator can now pause any agent in the organization.
* [`POST /tasks`](/api/create-task): Added the `source` field (`manual`,
  `brief`, `meeting`, `whatsapp`, or `agent`).
  [`GET /tasks`](/api/get-task-board) reports it for each card.
* [`GET /tasks`](/api/get-task-board), [`POST /tasks`](/api/create-task):
  The `display_id` of a card uses the organization's task ID prefix, or `GT`
  when the organization has none.
