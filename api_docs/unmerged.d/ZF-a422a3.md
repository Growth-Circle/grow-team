**Feature level ZF-a422a3**

* Agent profiles gained an `instructions` field the agent reads at the start
  of each task. `POST /agent/profiles`, `PATCH /agent/profiles/{profile_id}`
  accept it. `GET /agent/profiles`, `GET /agent/profiles/{profile_id}` report
  `has_instructions`, and an editor's `configuration` block reports the text.
  Changing it invalidates the profile's readiness check.
* Added `GET /agent/team-instructions`, `PATCH /agent/team-instructions`.
  Organization administrators set instructions every agent in the
  organization reads at the start of each new task.
* Added `POST /agent/pairings/preview`. It checks a pairing code and returns
  the device name, a fingerprint prefix, the organization name, and the
  expiry time, without approving the pairing.
* `GET /agent/profiles`, `GET /agent/profiles/{profile_id}`,
  `GET /agent/runners/{runner_id}`, `GET /agent/providers/{provider_id}`,
  `GET /agent/team-default`: agent providers report a `model_location`
  (`runner_local`, `private_network`, or `external`). An agent runner reports
  a `fingerprint_prefix` to its owner. An agent profile's `allowed_actions`
  gains `test_task` once its owner may send it a one-message readiness
  check.
* Fixed `GET /agent/team-default` and `PATCH /agent/team-default` reporting
  `has_default: true` to a reader who cannot see the team default agent. A
  non-administrator now sees `has_default: true` only when the response also
  includes the agent.
* Agent requests now report a stable `code` alongside their generic rejection
  message for a known, actionable failure: `audience_grant_required`,
  `team_instructions_stale`, and `instructions_rejected`.
* Added an `instructions_digest` on the agent runtime execution
  configuration and provider probe descriptors, and an `instructions` block
  on the agent runtime attempt descriptor. Added a `manage` agent task kind
  to the runner descriptor and selection schemas.
