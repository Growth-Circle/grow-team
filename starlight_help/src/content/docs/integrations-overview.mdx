Integrations let you connect sanji with other products. For example, you can get
notification messages in sanji when an issue in your tracker is updated, or for
alerts from your monitoring tool.

Use the [available integrations](/integrations/) for this deployment. You can
also connect an incoming webhook that uses the
[Slack-compatible format](/integrations/slack_incoming).

If you don't find an integration you need, you can:

* [Write your own integration](#write-your-own-integration).
* Report a sanji issue through the
  [project tracker](https://github.com/Growth-Circle/grow-team/issues).

## Set up an integration

### Native integrations

<Steps>
  1. [Search sanji's integrations](/integrations/) for the product you'd like to
     connect to sanji.
  1. Click on the card for the product, and follow the instructions on the page.
</Steps>

### Integrate via Zapier or IFTTT

If you don't see a native sanji integration, you can access thousands of
additional integrations through [Zapier](https://zapier.com/apps) and
[IFTTT](https://ifttt.com/search).

<Steps>
  1. Search [Zapier](https://zapier.com/apps) or [IFTTT](https://ifttt.com/search)
     for the product you'd like to connect to sanji.
  1. Follow the integration instructions for [Zapier](/integrations/zapier) or
     [IFTTT](/integrations/ifttt).
</Steps>

### Integrate via Slack-compatible webhook API

sanji can process incoming webhook messages written to work with [Slack's
webhook API](https://api.slack.com/messaging/webhooks). This makes it easy to
quickly move your integrations when [migrating your
organization](/help/import-from-slack) from Slack to sanji, or integrate any
product that has a Slack webhook integration with sanji .

<ZulipNote>
  **Note:** In the long term, the recommended approach is to use
  sanji's native integrations, which take advantage of sanji's topics.
  There may also be some quirks when Slack's formatting system is
  translated into sanji's.
</ZulipNote>

<Steps>
  1. [Create a bot](/help/add-a-bot-or-integration) for the Slack-compatible
     webhook. Make sure that you select **Incoming webhook** as the **Bot type**.
  1. Decide where to send Slack-compatible webhook notifications, and [generate
     the integration URL](/help/generate-integration-url).
  1. Use the generated URL anywhere you would use a Slack webhook.
</Steps>

### Integrate via email

If the product you'd like to integrate can send email notifications, you can
[send those emails to a sanji channel](/help/message-a-channel-by-email). The
email subject will become the sanji topic, and the email body will become the
sanji message.

For example, you can configure your personal GitHub notifications to go to a
sanji channel rather than your email inbox. Notifications for each issue or pull
request will be grouped into a single topic.

## Write your own integration

You can write your own sanji integrations using the well-documented APIs below.
For example, if your company develops software, you can create a custom
integration to connect your product to sanji.

For deployment-specific help, contact your server administrator.

### Sending content into sanji

* If the third-party service supports outgoing webhooks, you likely want to
  build an [incoming webhook
  integration](https://zulip.readthedocs.io/en/latest/webhooks/incoming-webhooks-overview.html).
* If it doesn't, you may want to write a
  [script or plugin integration](/help/non-webhook-integrations).
* The [`zulip-send` tool](/api/send-message) makes it easy to send sanji
  messages from shell scripts.
* Finally, you can
  [send messages using sanji's API](/api/send-message), with bindings for
  Python, JavaScript and [other languages](/api/client-libraries).

### Sending and receiving content

* To react to activity inside sanji, look at sanji's
  [Python framework for interactive bots](/help/running-bots) or
  [sanji's real-time events API](/api/get-events).
* If what you want isn't covered by the above, check out the full
  [REST API](/api/rest). The web, mobile, desktop, and terminal apps are
  built on top of this API, so it can do anything a human user can do. Most
  but not all of the endpoints are documented on this site; if you need
  something that isn't there check the
  [sanji source code](https://github.com/Growth-Circle/grow-team).
